# Intempt React Native example

A runnable Expo app that consumes `intempt-react-native`. It has two jobs.

## 1. Something you can actually run

Buttons for every contract method, with the result of each call on screen —
including which ones reject on which platform, so the gaps are visible rather
than described.

```sh
cd example
npm install
npx expo prebuild        # generates ios/ and android/, not committed
npm run ios              # or: npm run android
```

Credentials come from the environment, inlined by Expo at build time:

```sh
export EXPO_PUBLIC_INTEMPT_API_KEY=yourPrefix.yourSecret
export EXPO_PUBLIC_INTEMPT_ORG_ID=your-org
export EXPO_PUBLIC_INTEMPT_PROJECT_ID=your-project
export EXPO_PUBLIC_INTEMPT_SOURCE_ID=your-source
```

Without them the app starts and says so rather than crashing.

**Expo Go will not work.** This app uses a native module, so it needs a dev
build — `expo prebuild` then `expo run:ios`. That is a property of any SDK with
native code, not of this package.

## 2. The end-to-end test

With `EXPO_PUBLIC_INTEMPT_E2E=1` the app runs the full suite on mount and writes
the results to a file in its Documents directory. CI reads that file with
`simctl get_app_container`.

```sh
scripts/run-e2e-ios.sh          # from the repository root
```

The file matters. An earlier probe reported through `console.log`, which does
not reach `os_log` in a `--dev false` bundle — CI captured nothing while the app
ran perfectly. A scaffolded throwaway app could not fix that, because it cannot
carry a filesystem dependency. This one can.

## What it asserts

The interesting assertion is `flush()`, which resolves to the number of events
the **server** accepted. `track()` returning true only means the queue took it,
and a transport posting without an `Authorization` header produces perfectly
correct payloads while delivering nothing — a bug that shipped in
`intempt-android` and lost 100% of events.

Also covered, because these only exist end to end:

- typed values surviving the bridge — numbers stay numbers, booleans stay booleans
- `record()` using the frozen argument order
- consent transmitting **while opted out**
- `optOut()` discarding the queue rather than only setting a flag
- `reset()` rotating the profile id

## Note on `ios/` and `android/`

Generated by `expo prebuild` and deliberately **not committed**. They are build
output; committing them means every Expo or React Native upgrade arrives as a
merge conflict in generated code.
